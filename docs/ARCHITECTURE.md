# Архитектура первого этапа

**Актуальное решение 2026-09-06:** отдельный проект ChatGPT без обязательного OpenAI API. Готово локальное синтетическое ядро очереди `apps/bridge` и пакет `chatgpt-project`; транспорт и реальная интеграция сайта ещё отсутствуют. Автоматический запуск проекта и изоляция личных снов требуют проверки. [Архитектура этапа 03](stages/03-chatgpt-project-bridge.md), [контракт](../chatgpt-project/BRIDGE_CONTRACT.md). Далее сохранено описание работающего demo и прежних архитектурных планов.

Браузер → Next.js `/api/*` rewrite → FastAPI → SQLite и локальный Orchestrator. Браузер обращается к одному origin; ключи внешних провайдеров в frontend не предусмотрены. Распознавание речи отдельно выполняет браузерный SpeechRecognition, затем человек проверяет текст и отправляет его обычным путём.

API хранит записи и состояния задач на диске. Оркестратор запускает `asyncio.Task`, ограничивает параллельность до двух, общий таймаут ожидания/обработки — 45 секунд. После перезапуска незавершённая задача становится failed/interrupted, пользователь может повторить её; максимум три запуска. Это не долговечная распределённая очередь. Запускать **один API-процесс**, без `--workers`; автоматический reload на середине задачи также прерывает её. Demo выполняется быстро, и UI может сразу увидеть completed, не показывая искусственную задержку.

`Provider` — граница замены; сейчас единственная реализация `DemoProvider`. Она ищет шесть групп слов RU/EN и возвращает шаблон; если не находит ничего, возвращает пустой список, не выдумывает детали. P01–P14 сохранены отдельно как спецификация. Выходная схема проверяется Pydantic. Телеметрия demo содержит название, checksum шаблона, latency, нулевые tokens/cost; модель не указана. Полноценного safety/moderation-провайдера ещё нет, и эта версия не предназначена для медицинских или кризисных консультаций.

## Данные и глобальная локализация

`locale` — язык результата и интерфейса при отправке (`ru-RU`/`en-US` сейчас). `content_language` — добровольно заданный язык рассказа (по умолчанию `und`). `recognition_locale` — выбранный язык распознавания, если текст добавлен голосом. `region` — необязательное ISO-подобное двухбуквенное поле в API; UI его пока не собирает. `cultural_perspective` — добровольный свободный контекст, по умолчанию null. Демонстрация его не интерпретирует. Полей с автоматическим определением религии, национальности или убеждений нет.

RU/EN находятся в `apps/web/messages`, отдельно от компонентов. Локаль интерфейса меняется без изменения языка уже сохранённого результата. Для новых UI-языков нужны словарь и шаблон/провайдер результата; произвольный `content_language` уже сохраняется. Идентификаторы языков валидируются структурно, не по полному реестру BCP-47. RTL, полный перевод, пользовательский часовой пояс и локальные юридические тексты — следующие этапы. Будущие источники должны разделять язык оригинала, перевод, регион выборки, традицию и научный/культурный тип.

## Доступ и ограничения локального этапа

Случайный 256-битный гостевой токен, SHA256 в SQLite, HttpOnly/SameSite=strict cookie, проверка владельца на каждом чтении/повторе/удалении. UUID не заменяет проверку доступа. POST с ключом идемпотентности не дублирует запись; изменённое тело с тем же ключом отклоняется. Известные чужие browser-origin и cross-site mutations блокируются. Тела POST ограничены 64 KiB, пользовательский текст — 20–10 000 символов. Валидационные ошибки не включают исходный текст. Отдельный ID связывает events и first-touch attribution с сессией.

База содержит открытый текст; срок гостевой сессии — 24 часа, автоматического удаления базы пока нет. Ограничение запросов по сессии можно обойти созданием другой сессии или удалением записей, поэтому это не публичный abuse-control. Идемпотентность retry/creation действует в рамках сохраняемой записи. Требуются TTL/cleanup, consent/policy, secure-cookie поверх TLS, IP/guest/global budgets, безопасные backups и аудит перед публичным запуском. Сервис в поставляемых командах слушает loopback.

## Переход к целевой архитектуре

1. Перенести репозиторий Store на PostgreSQL через SQLAlchemy/Alembic: sessions, dreams, interpretations, ai_jobs, events, prompt_versions. Отделить результаты от текущей строки dreams, хранить версии генерации.
2. Вместо `asyncio.Task` сделать Celery workers + Redis; claim/lease, идемпотентность, retries/backoff, dead-letter состояние, лимиты стоимости и возраст очереди. Текущее recovery на старте не использовать при нескольких процессах.
3. Telegram/aiogram получает тот же application service и отдельный способ аутентификации; UI не дублирует бизнес-логику. Платежи через отдельный PaymentProvider, доступ только по серверному подтверждённому webhook.
4. MinIO для разрешённых медиа, Metabase для агрегатов; content worker отделён от consumer API. В этот этап не входят развёрнутые PostgreSQL, Redis, Celery, Docker, nginx или Terraform.

Основа выбора: [Next.js installation](https://nextjs.org/docs/app/getting-started/installation), [FastAPI background tasks и граница Celery](https://fastapi.tiangolo.com/tutorial/background-tasks/). Локальная очередь — осознанное упрощение, которое не подменяет финальную архитектуру документа.
