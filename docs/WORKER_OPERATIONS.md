## SSH-транспорт ПК → VPS — 2026-09-10

Если прямой HTTPS с ПК получает ConnectTimeout, но SSH работает, поддерживается
`pwsh -NoProfile -File scripts/start-worker.ps1 -Resume -SshTunnel`.
Перед сменой способа запуска остановить текущий воркер через stop-worker.ps1
и дождаться завершения активного задания. Флаг не меняет уже запущенный процесс.
Сторож создаёт SSH forward 127.0.0.1:3181 → VPS 127.0.0.1:3180, StrictHostKeyChecking,
BatchMode и keepalive. Локальный HTTP проходит внутри шифрованного SSH-транспорта;
публичный HTTPS и авторизация служебным токеном остаются прежними.
Переменная сервера переопределяется только в дочернем воркере, .env.worker не меняется.
Занятый порт не используется. При обрыве SSH выполняется переподключение с паузой
30 с; состояние доступности сервера всё равно определяется настоящим heartbeat.
Остановка воркера завершает принадлежащий этому сторожу SSH-процесс.
Это исправляет зависимость воркера от прямого HTTPS-маршрута данного ПК; доступность
сайта из сети каждого посетителя и самого ChatGPT требует отдельной проверки.

Для этого используются служебный API Sonnic и интерфейс браузера через Playwright/CDP. Модели не требуется вызывать MCP. Служебный секрет Sonnic не является ключом OpenAI API.

Этот документ описывает эксплуатацию реализованного транспорта. Он не подтверждает завершение всего продукта или конкретного живого прогона. Автоматический режим пока предназначен для вымышленных снов. Общая память проекта ChatGPT не обеспечивает проверенную изоляцию посетителей; голосовой путь с настоящим микрофоном и платежи не подтверждены. Новый чат и инструкция не использовать другие чаты сами по себе не решают проблему памяти.

Пользовательская кнопка удаления использует `DELETE /api/v1/bridge/jobs/{id}`:
сервер проверяет владельца, удаляет строку задания и связанный служебный claim,
а SQLite работает с `secure_delete=ON`. Старый POST `/cancel` оставлен только для
совместимости прежних клиентов и очищает полезную нагрузку. Ни один из этих путей
не удаляет чат ChatGPT или уже созданную резервную копию; интерфейс сообщает эту
границу прямо.

## Подготовка конфигурации

Все локальные команды ниже выполняются из корня репозитория Sonnic. Если `.venv` ещё отсутствует, создайте его штатным способом проекта. Зависимости исполнителя устанавливаются в то же окружение, что и зависимости API:

```powershell
.\.venv\Scripts\python.exe -m pip install -r apps/api/requirements.txt -r apps/worker/requirements.txt
```

Создайте локальный `.env.worker` по структуре `.env.worker.example`, сохраняя существующий файл, если он уже настроен. В этом документе значения секретов намеренно отсутствуют.

| Переменная | Где задаётся | Назначение |
| --- | --- | --- |
| `SONNIC_WORKER_SERVER` | `.env.worker` на ПК | HTTPS origin сервера Sonnic; тестовый адрес указан в `.env.worker.example` |
| `SONNIC_WORKER_CDP` | `.env.worker` на ПК | `http://127.0.0.1:9335`; другое значение исполнитель отвергает |
| `SONNIC_WORKER_TOKEN` | `.env.worker` на ПК и `deploy/.env` на VPS | Один и тот же случайный секрет минимум из 32 символов; передаётся только в заголовке служебных HTTPS-запросов |
| `SONNIC_AUTOMATIC_DISPATCH` | `deploy/.env` на VPS | Точная строка `true` включает служебный API и автоматическую выдачу |
| `SONNIC_WORKER_ALLOW_PERSONAL` | `deploy/.env` на VPS | Оставить отсутствующим или `false`: автоматическая очередь принимает только задания, помеченные как вымышленные |

Метка `synthetic` — декларация отправителя, а не автоматическая проверка отсутствия персональных данных в тексте. Для испытаний используйте действительно вымышленные сны. Переключение `SONNIC_WORKER_ALLOW_PERSONAL=true` технически открывает выдачу личных снов, но не устраняет ограничения общего проекта.

Переменные окружения процесса имеют приоритет над `.env.worker`. После изменения конфигурации требуется перезапуск соответствующего процесса. `.env.worker` и `data/` исключены из Git, но это не шифрование и не настройка прав доступа. Секрет не помещают в промпты, аргументы команд, скриншоты, логи или отчёты.

Существующие `SONNIC_BRIDGE_ORIGIN`, `SONNIC_BRIDGE_CLIENT_ID` и `SONNIC_BRIDGE_REDIRECT_URI` относятся к настройке сайта и диагностического MCP. Они не заменяют служебный токен. Развёртывание и изоляция контейнеров описаны в [deploy/README.md](../deploy/README.md). Этот исторический документ также описывает прежний ручной MCP-сценарий; автоматический цикл выполняется отдельным исполнителем.

При изменении `deploy/.env` контейнер API должен быть пересоздан с новой конфигурацией. Команды Compose выполняются на VPS из `/opt/sonnic/source/deploy` в проекте `sonnic`. Профиль ChatGPT и исполнитель остаются на ПК; в серверную сборку они не включаются.

## Вход и запуск

При первом запуске откройте выделенный браузер для обычного входа владельца:

```powershell
pwsh -NoProfile -File .\scripts\start-worker-browser.ps1 -Login
```

Войдите в ChatGPT в этом профиле и проверьте доступ к проекту Sonnic. Вход — одноразовая подготовка рабочего окружения, а не действие посетителя при каждой отправке сна. `-Login` делает видимым новый запуск. Если порт 9335 уже занят правильным профилем, скрипт только сообщает об этом и не открывает вторую копию или новое видимое окно.

Проверить доступность редактора проекта без выдачи задания и без запроса к служебному API можно так:

```powershell
.\.venv\Scripts\python.exe -m apps.worker.main --probe
```

Ожидаемый вывод — `browser_state:ready`. Проба использует тот же локальный замок, что и исполнитель: не запускайте её одновременно с работающим исполнителем. Успех пробы подтверждает доступность страницы и редактора, но не генерацию, лимит модели или доставку результата.

Обычный фоновый запуск:

```powershell
pwsh -NoProfile -File .\scripts\start-worker.ps1
```

При отсутствии stop/pause скрипт запускает отдельный Chrome при необходимости и скрытый сторож. Обычный запуск сохраняет оба маркера и при их наличии прекращается до запуска браузера. Только явно разрешённый оператором `-Resume` снимает маркеры. Повторный запуск при работающем Python-процессе Sonnic не создаёт второй исполнитель. Дополнительно применяются mutex сторожа и файловый замок исполнителя. Сообщение о запуске не означает, что сервер уже видит `ready`: это проверяется отдельно.

Для диагностики при остановленном стороже можно запустить один цикл в текущей консоли:

```powershell
.\.venv\Scripts\python.exe -m apps.worker.main --once
```

`--once` выполняет реальную операцию: может забрать одно задание, отправить его в ChatGPT или доставить сохранённый ответ. Это не проба только для чтения. При отсутствии задания он завершится после проверки очереди. Обычный процесс, `--once` и `--probe` учитывают оба маркера stop/pause: при их наличии сообщают серверу offline и завершаются до подключения к браузеру. Возобновление через `-Resume` требует отдельного решения оператора. Без параметров процесс продолжает опрос. Автоматический запуск после входа в Windows, перезагрузки или выключения ПК этими командами не устанавливается.

## Проверка состояния

Публичный `GET /api/v1/bridge/config` показывает `automatic_dispatch`, `worker_state`, `chatgpt_connected` и ограничения ввода. Запрос не требует служебного токена. `chatgpt_connected=true` вычисляется из недавнего `ready` или `busy`; это не гарантия успешного следующего ответа.

| `worker_state` | Значение и действие оператора |
| --- | --- |
| `ready` | Исполнитель проверил редактор проекта и готов искать задание |
| `busy` | Задание обрабатывается, аренда поддерживается |
| `login_required` | В выделенном профиле требуется вход либо доступ к проекту не подтверждён; проверить его обычным входом |
| `browser_unavailable` | CDP недоступен либо произошла ошибка Playwright; проверить порт 9335 и логи Sonnic |
| `model_limit` | В alert/dialog ChatGPT обнаружен текст о лимите; проверить аккаунт в выделенном профиле и дождаться восстановления доступности |
| `page_changed` | Ожидаемый редактор или структура страницы недоступны; требуется проверка и, возможно, исправление адаптера |
| `offline` | Heartbeat старше 45 секунд либо автоматический режим отключён; проверить ПК, сеть и процесс |

В локальном логе дополнительно бывает `worker_state:server_unavailable`: запрос к серверу завершился ошибкой HTTP или сети. Это общее обозначение, поэтому нужно различать недоступность сервера и ошибку конфигурации. Служебный API отвечает `401 invalid_worker_token` при неверном секрете и `503 dispatch_disabled` при выключенном режиме. `409` обозначает конфликт состояния очереди или аренды. Не публикуйте диагностический запрос с заголовком Authorization.

Логи можно читать без открытия файлов с содержимым сна:

```powershell
Get-Content -LiteralPath .\data\worker\worker.log -Tail 30
Get-Content -LiteralPath .\data\worker\worker-error.log -Tail 30
Get-Content -LiteralPath .\data\worker\watchdog.log -Tail 30
```

Сторож перенаправляет стандартные потоки в `worker.log` и `worker-error.log`; при новом запуске дочернего процесса эти файлы используются заново, поэтому они не заменяют долговременный архив. `watchdog.log` дополняется записью о перезапуске. `receipts.jsonl` сохраняет идентификаторы, URL чата, итог и время, без текста сна и ответа.

## Сроки, аренда и повторы

| Ограничение | Текущее поведение |
| --- | --- |
| Общий срок автоматического задания | 600 секунд от постановки в очередь, включая ожидание; `create_app` задаёт это значение для автоматического режима |
| Ручной режим | 3600 секунд; это не срок автоматического задания |
| Аренда автоматического задания | 120 секунд, ограничена общим сроком задания |
| Продление и `busy` | Каждые 15 секунд при обработке; продление не сдвигает общий срок |
| Ожидание генерации | До 480 секунд от сохранённого намерения отправить сообщение; перезапуск не обнуляет этот срок |
| Завершённость ответа | Подтверждены задание и аренда в последнем сообщении пользователя; ответ и элемент обратной связи находятся после него; нет кнопки остановки потока; текст стабилен не менее 3 секунд; при непригодном JSON адаптер ждёт до 15 секунд стабильности перед ошибкой |
| Опрос после обычного цикла | Пауза 5 секунд; сама проверка браузера тоже занимает время |
| Свободная вкладка проекта | Автоматического reload нет; читается текущий DOM. При восстановлении после перенаправления адаптер может открыть проект |
| После ошибки браузера, входа, блокировки или неопределённой отправки | Постоянная pause.requested; автоматического возобновления нет |
| После ошибки связи с сервером Sonnic | Пауза 30 секунд; сохранённая стадия доставки повторяется без подключения к браузеру |
| Перезапуск упавшего исполнителя | Пауза 15 секунд; максимум два автоматических перезапуска за запуск сторожа, после третьего неожиданного выхода — pause.requested |
| Активные задания | Не более 20 суммарно в состояниях `queued`, `leased`, `awaiting_review`; обрабатывается одно арендованное задание |
| Попытки задания | Не более 3; новая попытка после `failed` или `expired` требует запроса retry со стороны владельца задания |

При истечении общего срока или аренды очередь переводит активное задание в `expired`. Это выполняется при следующей операции с очередью; отдельного таймера, мгновенно меняющего строку базы, нет. При недоступном исполнителе новые автоматические задания отвергаются с `503 worker_unavailable`. Уже поставленное задание ограничено своим сроком.

Лимит в три попытки задания и лимит неожиданных завершений процесса учитываются отдельно. Диагностированная ошибка `BrowserFailure` во время генерации передаётся серверу как ошибка текущей попытки; ошибки из списка постоянной паузы также останавливают дальнейшую работу. Обрыв Playwright ставит паузу, обрыв связи с VPS сохраняет журнал для восстановления. Цель 30–40 секунд из плана не является настроенным таймаутом или гарантией скорости.

## Восстановление и сохранность результата

До запроса выдачи, отправки сообщения и доставки результата исполнитель сохраняет соответствующую стадию в `data/worker/active.json` через временный файл и атомарную замену. Этот файл может содержать полный пакет сна и готовый ответ. Не удаляйте и не редактируйте его для «разблокировки» работающего исполнителя.

| Стадия журнала | Что происходит после восстановления |
| --- | --- |
| `claiming` | Повторяется claim с тем же `claim_key`; ответ на потерянную выдачу не создаёт другую аренду |
| `claimed` | Задание получено, намерение отправки ещё не зафиксировано; после успешной проверки и продления аренды исполнитель может начать новый чат |
| `sending` | Намерение записано до Enter; ищется уже открытый чат проекта по идентификаторам задания и аренды в последнем сообщении пользователя, повторное нажатие Enter автоматически не выполняется |
| `sent` | Сохранён URL чата; исполнитель продолжает читать этот чат, при необходимости открывая сохранённый URL |
| `delivery` | Сохранён готовый результат или код ошибки; повторяется доставка на VPS без подключения к браузеру и новой генерации |

Перед запуском или возобновлением генерации исполнитель сначала подтверждает действующую аренду на VPS. При неоднозначности отправки возвращается `submission_uncertain`. Нельзя считать это доказательством, что ChatGPT не получил сообщение. Оператор проверяет связанный чат перед решением о новой попытке. Полное exactly-once создание чата при аварии браузера не гарантируется.

Идентификаторы задания и аренды стоят в первой строке промпта, чтобы длинное свёрнутое сообщение сохраняло связь с текущей попыткой. На первоначальную загрузку DOM отводится 20 секунд: до подтверждения последнего сообщения ответ не читается и URL не записывается. После подтверждения смена сообщения или URL прекращает обработку. Принимается только HTTPS URL чата внутри фиксированного проекта Sonnic, без query и fragment; сохранённый URL не перепривязывается к другому чату.

Сервер проверяет идентификаторы задания и аренды, номер попытки, хеш входа, язык, схему ответа и дословное присутствие цитат в исходном сне. Автоматический результат после проверки получает `completed` без обязательного ручного принятия. Техническая проверка не оценивает смысловую правильность интерпретации. Ручной MCP-сценарий по-прежнему может использовать `awaiting_review`.

Повторная доставка того же результата идемпотентна. Отменённая задача, истёкшая аренда и устаревшая попытка не допускают позднюю публикацию. При подтверждённом ответе сервера журнал заменяется квитанцией; при сетевой ошибке он остаётся для повторной доставки. Авторитетный отказ `409` или `422` завершает локальную доставку как `delivery_rejected`, без повторной генерации. После итогового подтверждения или отказа адаптер закрывает свою текущую вкладку задания, если ссылка на неё сохранилась в процессе. Он не удаляет чат в ChatGPT и не закрывает все вкладки профиля.

Другие полезные итоги в логе и квитанциях:

- `generation_timeout` — за отведённое время законченный ответ не получен.
- `invalid_model_output` — финальный текст не прошёл проверку JSON, связи с заданием или цитат.
- `lease_rejected` — сервер отклонил аренду; чтение результата прекращено.
- `claim_expired` — сохранённый claim больше не относится к активной аренде.
- `job_finished:completed` — сервер подтвердил публикацию; затем нужно проверить результат на странице владельца задания.

Кнопка удаления на сайте вызывает `DELETE`: физически удаляется строка задания и связанная запись выдачи на сервере. Она не удаляет автоматически чат в ChatGPT, профиль Chrome, локальную копию уже выданного пакета или резервные копии. Удаление и сроки хранения этих копий требуют отдельного эксплуатационного решения до обработки личных снов.

## Остановка только Sonnic

Штатная остановка:

```powershell
pwsh -NoProfile -File .\scripts\stop-worker.ps1
```

Скрипт создаёт `data/worker/stop.requested` и до 20 секунд наблюдает за Python-процессом только этого репозитория. При необходимости время наблюдения задаётся через `-WaitSeconds`. Это не предельное время обработки и не принудительное завершение: скрипт никого не убивает. Если работа продолжается, он сообщает, что остановка запрошена.

Исполнитель проверяет маркер между циклами: текущая генерация и доставка могут завершиться, затем процесс отправляет `offline` и выходит. Сторож видит тот же маркер и не перезапускает его. При ошибке сети текущий цикл может закончиться с сохранённой недоставленной записью; маркер остановит процесс до следующего повтора доставки. Запись остаётся для следующего запуска, но серверная аренда продолжает истекать. Для ожидания подтверждённой доставки проверьте `receipts.jsonl`, состояние задания на сайте и отсутствие процесса, а не только завершение stop-скрипта.

Для аварийного ручного завершения сначала останавливают сторож, затем исполнитель, проверяя полный путь к `scripts/watch-worker.ps1` данного репозитория либо полный путь к `.venv/Scripts/python.exe` и аргументы `-m apps.worker.main`. Завершение всех `python.exe`, `pwsh.exe` или `chrome.exe` недопустимо: они могут принадлежать другим задачам.

Штатная остановка оставляет выделенный Chrome открытым. Если требуется закрыть и его, проверяйте процесс слушателя 9335 и аргумент `--user-data-dir` с полным путём к `data/worker/chrome-profile` Sonnic; при несовпадении ничего не закрывайте. Не удаляйте профиль или `active.json`: они нужны для входа и восстановления. Если сообщение `offline` не доставлено, сервер покажет его после истечения 45 секунд с последнего heartbeat; незавершённая аренда может истечь.

Сервер останавливается отдельно, из каталога `/opt/sonnic/source/deploy` на VPS:

```sh
docker compose stop
```

Команда затрагивает Compose-проект `sonnic`. Не останавливайте системные nginx или Docker и не используйте `docker compose down -v`: том `sonnic_data` содержит данные очереди. Остановка серверных контейнеров не останавливает исполнитель на ПК; для полного обслуживания остановите обе части.

### Резервная копия и проверка восстановления

`scripts/backup_sonnic.py` создаёт новую папку с двумя SQLite-копиями: основной
базой и базой очереди с суффиксом `.bridge.sqlite3`. Исходные файлы открываются
только для чтения. Уже существующая папка назначения не перезаписывается.
Манифест содержит контрольные суммы и количества строк, без содержимого записей.
Команда `verify` проверяет суммы, восстанавливает копии во временные отдельные
базы, проверяет SQLite integrity_check и количества строк. Рабочую БД она не заменяет.

Чтобы получить согласованную пару баз, перед созданием копии остановите компоненты
Sonnic, а после проверки запустите их снова. На текущем VPS выполнена эта процедура:
две базы скопированы, изолированное восстановление обеих прошло. Копия размещена
в `/opt/sonnic/backups`, папка имеет права 700, файлы 600. Исполнитель оставался
выключенным; данные живой очереди не заменялись.

Последняя копия `/opt/sonnic/backups/verified-20260908T222133` повторно проверена
командой `verify` после запуска сервисов. Проверка вернула две восстановленные базы
и `isolated_restore=true`. Команде передавался только путь к папке резервной копии:
путь рабочей БД не передавался, контейнеры не останавливались, файлы копии и рабочая
БД не изменялись. Временные восстановленные базы удалены после проверки. Этот тест
подтверждает читаемость последней локальной копии, но не восстановление на другом
сервере после потери VPS.

2026-09-09 снимок дополнительно скопирован по SSH на рабочий ПК. Новый скрипт
`scripts/backup-offsite.ps1` проверяет входные SQLite-копии, шифрует ZIP через
Windows DPAPI CurrentUser, расшифровывает его и проверяет изолированное восстановление
обеих БД. Сохранённый архив повторно проверен отдельным запуском `-Verify`.
Путь: `%LOCALAPPDATA%/Sonnic/Backups/verified-20260908T222133.dpapi`.
SHA-256: `42E7A638A48897D6421C066BB8AADE96A9759198FC4676113BF40ECFC9ED7BE0`.

Архив и временная папка доступны только текущему пользователю Windows и SYSTEM;
расшифрованная временная папка удаляется после проверки, в том числе при ошибке.
Повреждение архива и попытка перезаписать существующий файл отклоняются; три
Windows-теста используют только синтетические БД и не подключаются к SSH.
Скрипт не останавливает сервисы и забирает только ранее созданный согласованный
снимок с фиксированными именами файлов. Свежую копию рабочих БД он не создаёт.

```powershell
pwsh -NoProfile -File scripts/backup-offsite.ps1 -SshHost sprintbox-itp -RemoteFolder /opt/sonnic/backups/verified-20260908T222133 -Archive "$env:LOCALAPPDATA/Sonnic/Backups/verified-20260908T222133.dpapi"
```

Это ручная внешняя копия, зашифрованная для этой учётной записи Windows.
Копирование `.dpapi` на другой компьютер не гарантирует расшифровку: переносимый
ключ восстановления не создан. Расписание Codex описано выше; независимое хранилище,
доступное при потере ПК, и сроки хранения ещё не настроены. Копия сохраняет удалённые позднее записи до
своего удаления. При потере одновременно VPS и профиля Windows этот механизм
сам по себе не обеспечивает восстановление.

Пример запуска из остановленного окружения (пути задаёт оператор):

```text
python scripts/backup_sonnic.py create --main /path/sonnic.sqlite3 --destination /private/new-backup --api-stopped
python scripts/backup_sonnic.py verify /private/new-backup
```

Для отдельно разрешённого контрольного запуска одного задания без сторожа есть
`python -m scripts.validate_worker_once --live --resume --start 6` (из `.venv`).
Перед ним проверьте отсутствие действующих заданий в очереди и работающего сторожа.
Команда явно снимает stop/pause, поэтому не является проверкой только для чтения.
Она обрабатывает не более одного задания, ограничивает цикл 120 секундами и в
`finally` возвращает stop.requested и отправляет offline. Запуск запрещён при
незавершённом локальном задании, кроме пустой стадии claiming. Отчёт сохраняется
в отдельную папку control с UTC-временем; предыдущие свидетельства не заменяются.
Ошибка проверки сайта не означает неуспех генерации: сначала сверьте квитанцию
и серверную запись, не повторяйте отправку сна ради восстановления отчёта.

Изучение кода и локальные тесты не заменяют живой прогон сайт → очередь → ChatGPT → результат на сайте. `--probe` не выполняет этот прогон. Скрипт `scripts/validate_worker_live.py --live` создаёт реальные задания с вымышленными текстами и расходует доступные запросы ChatGPT; это отдельная проверка, а не команда обязательного запуска исполнителя. Его артефакты сохраняются в `data/worker/validation`.

Для приёмки требуются сохранённые результаты серии RU/EN, измеренное время от отправки до показа, проверки отмены, потери сети, перезапуска и серверной изоляции посетителей. Проверка `404` для чужого задания подтверждает серверную границу доступа; она не подтверждает изоляцию памяти проекта ChatGPT. Дальнейшие критерии продукта перечислены в [STATUS_AND_COMPLETION_PLAN.md](STATUS_AND_COMPLETION_PLAN.md).
