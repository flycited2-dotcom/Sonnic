# Этап 01 — локальная основа Sonnic

Завершён 5 сентября 2026 года. Результат: первый локальный путь «ввод сна → фоновая обработка → бесплатный демонстрационный результат» на Next.js и FastAPI. Это проверенный технический прототип; содержательная работа настоящего AI ещё не подключена.

## Цель и границы

Дать владельцу запускаемую основу без необходимости писать код. Сохранить исходный DOCX и полную дорожную карту: web/Telegram, free/full, дневник, Premium, визуализация и отдельный контент-контур с атрибуцией. В текущий этап входят текстовый ввод, браузерная диктовка, RU/EN, добровольный контекст, гостевой доступ, локальное хранение и внутренняя исследовательская библиотека.

Не входят: реальные AI-запросы, поиск по библиотеке, платежи, Telegram, полноценный дневник, публикация сайта/контента, production-инфраструктура и полный перевод на все языки.

## Решения и обоснования

- Next.js + FastAPI соответствуют blueprint. Для первого запуска выбраны SQLite и фоновые задачи одного процесса, чтобы обойтись без Docker/VPS. PostgreSQL, Redis/Celery и миграции остаются следующим инфраструктурным шагом.
- DemoProvider выделен отдельно и честно маркирует результат. Он находит слова из небольшого списка и возвращает подготовленный текст; не выдаёт его за персональную интерпретацию. Если слов нет, показывает пустой список вместо вымышленных символов. Исходные P01–P14 сохранены отдельно.
- Локализация заложена сразу по новому указанию владельца, заменяющему прежнее исключение многоязычности. UI-строки RU/EN вынесены в словари. Язык интерфейса, рассказа, распознавания, регион и добровольная культурная перспектива разделены. Религия и национальность не угадываются.
- Голос реализован через Web Speech API браузера: начать, остановить и вставить окончательный текст, отменить, затем исправить текст перед отправкой. Незавершённые результаты показываются отдельно. Исходный текст при отмене или ошибке сохраняется. Во время диктовки отправка блокируется. Аудиофайлы Sonnic не создаёт. Браузер может использовать внешний сервис распознавания; уведомление видно до запуска микрофона.
- 12 источников в `docs/research` содержат библиографию, собственные заметки, ограничения, выборки, происхождение, язык и статус прав. Полные личные корпуса не загружены. Подборка включает Японию, шведоязычную выборку и межкультурное сравнение BaYaka/Hadza, но не претендует на мировой репрезентативный охват. Каталог не подключён к runtime.
- Клиентский экран остаётся понятным; сведения о подходе доступны отдельно. Используются контекстные гипотезы без прогнозов, диагнозов и выводов о чужих поступках. Научный аппарат не вставляется в каждый абзац.

Выполненные команды из корня:

```powershell
.venv\Scripts\python.exe -m pytest -q --basetemp=.cache/pytest --tb=short
npm.cmd run typecheck
npm.cmd run build
npm.cmd run test:e2e
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/start.ps1
```

Браузерная проверка завершилась `24 passed`, код выхода 0. Среда Codex мешала автоматическому завершению дочерних тестовых серверов; после остановки только созданных этим запуском процессов тестовый runner корректно завершился. Проверка пользовательского launcher отдельно прошла с разрешённым выполнением дочерних процессов. Это ограничение среды автоматизации, не провал сценариев. Для обычного локального запуска права администратора специально не требуются.

В pytest остались два предупреждения устаревания внутри Starlette/httpx/AnyIO; ошибок тестов нет. Сведения о версиях зафиксированы в package-lock.json и requirements.txt. При установке npm сообщил об отсутствии известных уязвимостей в установленном дереве; это не полноценный аудит безопасности.

## Ограничения, которые нельзя потерять при продолжении

**Живая диктовка через реальный микрофон не проверена.** Мобильные тесты — эмуляция viewport в Chrome, не реальный iPhone/Safari. Доступность и качество распознавания зависят от браузера, языка, региона, сети и разрешения. Sonnic не управляет обработкой/хранением у поставщика браузерного сервиса; отмена не отзывает уже переданный звук. Для стабильной поддержки всех целевых браузеров может понадобиться отдельный провайдер транскрипции.

**Настоящий AI и поиск по библиотеке не подключены.** Здесь нет проверки качества персональных интерпретаций или полноценной safety-модерации. Нужны серверный адаптер, согласованный провайдер/ключ и содержательные проверки до включения реального режима; просто добавить ключ в env недостаточно.

SQLite хранит текст без шифрования; сессия действует 24 часа, автоматического удаления по сроку нет. Loopback-only запуск, один API-процесс. Локальная очередь не заменяет Celery; незавершённые задачи после рестарта требуют повтора. Ограничение запросов на сессию не защищает публичный сервис. Штатное удаление из базы не гарантирует физическое стирание остаточных байтов диска. Не публиковать текущую версию как production.

Docker, PostgreSQL, Redis/Celery, Telegram, платежи, публичный деплой и запуск на других ОС не проверялись и не заявлены реализованными. На старте и завершении этого этапа папка не была Git-репозиторием; коммиты и удалённая публикация не выполнялись.

## Следующий шаг

Владелец может открыть Start-Sonnic.cmd и проверить UX, включая живую диктовку в своём браузере. Следующий технический этап — настоящий провайдер разборов с P13 → P01 → P02, JSON-валидацией и оценкой качества RU/EN. Поиск по разрешённым источникам подключается явно и отдельно. Нужны выбор провайдера и безопасно настроенный ключ; вопросы серверов, оплат и других языков решаются по мере соответствующих этапов.

## Исправление диктовки — 2026-09-05

После сообщения владельца о немедленном сбросе обнаружены ошибки обработки жизненного цикла: окончание без результата ошибочно считалось тишиной, а фразы при network/timeout терялись. Теперь неожиданное end имеет отдельное сообщение; «Слушаем» появляется только после audiostart; старт, остановка и сессия ограничены таймаутами. Синхронные ошибки также освобождают форму. При ошибке или незавершённой фразе текст доступен для редактирования и явной вставки, исходный черновик сохраняется. Перезапусков микрофона нет. Диагностика остаётся в памяти страницы и содержит только код, события и длительность.

В UI добавлены инструкции для обычного Chrome и системной диктовки Windows (Win+H). Само наличие Web Speech API не доказывает работоспособность внешнего сервиса. Причина конкретного сбоя пользователя пока не подтверждена: открытый экран показывал результат, а не ошибку диктовки. Реальный микрофон ассистент не включал.

Основания: [MDN end](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition/end_event), [MDN errors](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognitionErrorEvent/error), [Microsoft voice typing](https://support.microsoft.com/en-us/accessibility/windows/use-voice-typing-to-talk-instead-of-type-on-your-pc).
