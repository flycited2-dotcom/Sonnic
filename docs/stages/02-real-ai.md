# Этап 02 — серверный AI-адаптер

**Обновление 2026-09-06:** API-путь отложен по решению владельца. Текущий путь — новый отдельный проект ChatGPT и мост без API-ключей; см. [этап 03](03-chatgpt-project-bridge.md). Код этого этапа сохранён. Инструкции настройки API ниже исторические/опциональные, не обязательное продолжение.

Дата: 2026-09-05. **Код и проверки без сети готовы. Настоящие ответы модели ещё не получены: ключ API не настроен.** Демо оставлено работающим на http://127.0.0.1:3000.

## Что изменилось

Добавлен OpenAI Responses adapter. Первая операция совмещает задачи P13/P01: проверяет характер запроса и выделяет до шести деталей с дословными цитатами. Вторая операция адаптирует P02: строит разбор конкретного рассказа. Третья проверяет проект ответа по исходному сну и правилам; отклонённый текст не показывается. Модельная проверка не гарантирует правильность и безопасность — требуется оценка живых ответов.

Версия `packages/prompt_registry/real-v1.json` отделена от неизменённого blueprint-v1. Схемы этого этапа компактнее исходного полного extractor: symbols + safety_action, затем title/summary/key_connection/reflection_question. Принятое исключение для короткого рассказа: меньше трёх образов и 40–110 слов вместо искусственного дополнения; для подробного сна ориентир 120–220 слов. Длина проверяется в символах, соответствие ориентиру слов — при оценке качества. Тон пробуждения берётся из явно заполненного поля, а не придумывается.

JSON проверяется сервером через Pydantic, неизвестные поля запрещены, evidence должен буквально входить в исходный текст. Locale задан пользователем; язык, регион и культура не используются для угадывания убеждений. Поля mode/evidence_basis/research_retrieval_used задаёт сервер. Поиск по библиотеке не подключён и всегда отмечен false. Названия пяти будущих разделов статичны; текст реального разбора берётся из ответа модели.

Ошибки авторизации, лимита, сети, отказа модели, неподходящего JSON и проверки содержания различаются. При сбое не подставляется demo. Реальная опасность наяву, если она распознана моделью, направляется к сообщению поддержки вместо трактовки. Сны о травмах сами по себе не должны блокироваться. Нет утверждения о полноценной медицинской/производственной safety-системе.

Один внешний вызов ограничен 30 секундами; весь job с ожиданием очереди — 100 секундами, цикл polling — 110 секундами. До трёх внешних вызовов на попытку. Автоматических платных повторов нет; ручной retry ограничен тремя попытками и отключён для отказа/поддержки/ошибки ключа. Удаление отменяет локальную задачу; уже отправленный внешний запрос нельзя считать отозванным или бесплатным.

Телеметрия отделена для каждого job: версии и checksum промптов, schema version, имена моделей, длительности, доступные input/output token counts и статус вызовов. Нет текста сна, аудио, содержимого ошибки или ключа. Неизвестная стоимость — null, а не фиктивный ноль. Используется `store=false`, официальный фиксированный endpoint без редиректов, без инструментов и автоматических повторов. Это не заявление о нулевом хранении у провайдера.

## Подключение владельцем

В корне уже подготовлен игнорируемый `.env`. Он оставлен в безопасном demo-режиме, ключ пуст. Для включения:

1. В своём OpenAI API project создайте ключ и настройте доступный бюджет API. Вставьте ключ **только локально** в `OPENAI_API_KEY` внутри `.env`, не в чат. Подписка Codex сама по себе не настраивает доступ продукта Sonnic к API.
2. В этом же файле установите `AI_MODE=real` и `AI_ALLOW_PAID_REQUESTS=true`. Две модели уже указаны как стартовый вариант `gpt-5.4-mini-2026-03-17`; доступность именно вашему API project пока не проверена. Это кандидат для оценки, не подтверждённое качество разборов. При необходимости замените OPENAI_EXTRACT_MODEL / OPENAI_FREE_MODEL на доступные модели с Responses + Structured Outputs.
3. Скопируйте несохранённый черновик, остановите Sonnic клавишей Enter в окне запуска и снова откройте Start-Sonnic.cmd. После обновления страницы должен появиться AI-режим и уведомление о передаче текста OpenAI. Только отправка сна вызывает модель.

Приложение читает только проектный `.env` и явно установленные переменные окружения. Нет поиска ключей в настройках других приложений. При неполных real-настройках API откажется запускаться, а не включит демо тайно. Для возврата достаточно `AI_MODE=demo` и перезапуска.

## Проверки и критерии приёмки

- 33 API-теста прошли: demo/real path, JSON schema, grounding цитат, отказ/ошибки/таймауты, отсутствие подмены и утечки в телеметрии, идемпотентность/владение/удаление. Внешние ответы — только MockTransport.
- TypeScript и production build прошли.
- 26 проверок диктовки и 12 проверок demo/real UI прошли в desktop/mobile Chrome; реальная сеть AI и настоящий микрофон не использовались. Мобильный screenshot результата проверен; это синтетический ответ для проверки UI.
- `scripts/evaluate_ai.py` без аргументов проверяет семь синтетических входов без сети. **Живое качество не оценено.**

После настройки и отдельного осознанного запуска `.venv\Scripts\python.exe scripts/evaluate_ai.py --live` будет до 21 платного вызова. Результаты сохранятся в `.cache/quality/live-report.json`. Проверяются подсказки по упоминанию деталей и сходство ответов; обязательна ручная оценка по критериям каждого случая. Лексические проверки не доказывают отсутствие галлюцинаций.

Главный кейс: «приснился синий попугай» — учесть цвет и птицу, не выдумать клетку/разговор/полёт/эмоции; спросить об отсутствующем действии или чувстве. Не добавляли «попугай» в словарь demo. Другие случаи: красный велосипед у закрытой двери; спокойное и штормовое море с разными чувствами; офис с деревьями; обычный сон о травме; русский рассказ с английским UI без вывода о культуре.
