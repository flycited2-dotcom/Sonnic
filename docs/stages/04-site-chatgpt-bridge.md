# Этап 04 — связь сайта с проектом ChatGPT

Статус на 2026-09-06: **в работе; внешнее подключение не выполнено**. Этот файл уточняет состояние транспорта после этапа 03. Наличие загруженных источников и успешный ручной тест в ChatGPT не означают, что сайт уже получает ответы через MCP.

## Цель и границы

Проверить путь «синтетическое задание на сайте → запрос оператора в проекте ChatGPT → MCP `claim_job` → разбор → MCP `submit_result` → проверка и показ на сайте» без OpenAI API key. На этом этапе принимаются подготовленные вымышленные случаи. Личные сны и изоляция данных разных клиентов требуют отдельной проверки.

Существующий проект: [Sonnic — база знаний и разбор снов](https://chatgpt.com/g/g-p-6a9c47e07510819197bd898c90d1b12b-sonnic-baza-znanii-i-razbor-snov/project). Инструкции и 11 источников загружены на этапе 03; дубликат проекта не нужен.

## Реализация и решения

- `apps/bridge/http.py`: маршруты сайта, JSON Streamable HTTP MCP, инструменты `claim_job` и `submit_result`.
- `apps/bridge/oauth.py`: предопределённый OAuth-клиент, PKCE S256, привязка токена к владельцу и ресурсу, ограниченные сроки и отзыв доступа. Это авторизация Sonnic, а не ключ OpenAI API.
- `apps/web/app/bridge/`: создание задания, ожидание, проверка кандидата, показ результата и страница согласия OAuth.
- Изолированный внешний шлюз и запуск подготавливаются отдельно. Его готовность и доступность извне ещё не подтверждены.

ChatGPT выступает MCP-клиентом: оператор выбирает подключённое приложение в диалоге и отправляет запрос. Такой обмен описан в [OpenAI Docs: Developer mode](https://developers.openai.com/api/docs/guides/developer-mode) и [подключении HTTPS MCP](https://developers.openai.com/plugins/build/app-quickstart#connect-your-mcp-server-in-chatgpt). Документированный способ автоматического запуска выбранного ChatGPT Project из backend сайта не установлен. Создание задания в очереди само по себе не запускает ChatGPT.

Secure MCP Tunnel не используется: его [предварительные требования](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels#before-you-start) включают runtime API key. Для обычного HTTPS MCP нужен доступный извне адрес и собственная авторизация; ключ OpenAI API не требуется.

## Текущая остановка

В настройках ChatGPT режим разработчика выключен. Попытка включения отклонена автоматической проверкой со следующим объяснением:

> Включение режима разработчика — постоянное расширение доступа к непроверенным коннекторам и ослабление защит ChatGPT; требуется явное подтверждение непосредственно перед этим действием.

Нужно явное подтверждение пользователя именно на включение Developer mode. Это требование автоматической проверки конкретного действия, а не отсутствие ранее согласованной цели проекта. Обход не выполнялся. Локальная реализация и проверки, не зависящие от этого переключателя, продолжаются.

## Последовательность внешнего подключения

1. После подтверждения включить Developer mode и создать draft-приложение Sonnic в ChatGPT Plugins. Проверить, что его инструменты доступны в диалоге существующего проекта.
2. Подготовить отдельный HTTPS origin тестового шлюза с необходимыми страницами и маршрутами. Не открывать наружу общий демонстрационный сервер и его личные данные. Сверить извне HTTPS, OAuth metadata и ответ `401` с `WWW-Authenticate` на неавторизованный `/mcp`.
3. Установить `SONNIC_BRIDGE_ORIGIN` равным этому origin. В приложении указать HTTPS `/mcp` и OAuth. Сверить предопределённый `SONNIC_BRIDGE_CLIENT_ID` с настройкой клиента и поддержкой метода `none`. Текущий сервер защищает также discovery MCP; Mixed Auth ему не соответствует.
4. Скопировать **точный redirect URI из страницы приложения ChatGPT** в `SONNIC_BRIDGE_REDIRECT_URI`. Документация описывает стабильный callback при issuer identification, но значение нельзя угадывать. См. [OAuth и redirect URI](https://developers.openai.com/plugins/build/auth#redirect-url).
5. Открыть тестовую `/bridge` через тот же публичный HTTPS origin и в том же браузере, где будет согласие OAuth. Создать задание и разрешить подключение. Задание с `127.0.0.1` и согласие на внешнем домене используют разные cookie-сессии и разных владельцев; перенос владельца по идентификатору задания не разрешается.
6. Выбрать приложение в диалоге проекта, передать сформированное задание, проверить реальные вызовы `claim_job` и `submit_result`. Если интерфейс не поддерживает предопределённого public-клиента, сначала реализовать и проверить документированный CIMD или другой совместимый OAuth-вариант; не отключать авторизацию. CIMD сейчас не реализован.
7. На сайте проверить корреляцию и содержание кандидата, принять его и убедиться в показе результата. Сохранить фактическую трассу теста без токенов. Повторить проверку чужого владельца, отмены, истечения разрешения и отзыва доступа.

Текущий access token действует 15 минут; refresh не реализован. Это допускает короткий тест, но постоянное соединение потребует проверки повторной авторизации или добавления refresh. Требования клиента к OAuth и CIMD: [Authentication](https://developers.openai.com/plugins/build/auth).
