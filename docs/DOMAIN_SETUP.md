https://сонразбор.рф/bridge и оба имени с `www` направляют на основной адрес
через HTTP 308. Это штатное поведение: у посетителя один адрес и одна гостевая

## Проверки 1 октября

На VPS строгая проверка TLS для пяти имён, включая старый тестовый адрес,
прошла: конечная страница отвечает HTTP 200, дополнительные новые имена
возвращают ожидаемый 308. Девять CSS/JS-ресурсов ответили 200.
Гостевая cookie имеет `Secure`, `HttpOnly`, `SameSite=Strict` и host-only область;
два запроса с неверным Origin отклонены с 403. Серверный набор проверок перед
добавлением дальнейшей CDP-диагностики: 247 passed, 3 skipped.

На ПК владельца после ручного переподключения Happ основной адрес открылся;
повторная строгая TLS-проверка дала 200. Оба кириллических имени вернули
308 → 200, старый тестовый адрес — 200. Для `www.sonrazbor.ru` на этом ПК
ещё наблюдалось несоответствие имени сертификата. На VPS тот же адрес проходит
строгую проверку TLS. Ошибка локализована на сетевом пути ПК через Happ,
а не в серверной настройке домена; вероятен оставшийся внутренний кэш или
перенаправление по имени. Точный механизм внутри Happ не подтверждён.
Публичный DNS и Windows DNS-кэш уже содержат новый IP; ожидание DNS не является
исправлением этого отдельного симптома. Проверку сертификата не отключать.

Независимое хранение ключа и архива подтверждено владельцем; срок хранения
