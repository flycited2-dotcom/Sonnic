# Фронтенд Sonnic: готовность и оставшиеся работы

Обновлено 2026-09-09. Рабочий публичный вход — `/bridge`; серверный шлюз направляет
корневой адрес туда. Исторический локальный экран `/` остаётся демонстрационным
стендом и не является публичным пользовательским сценарием.

## Бесплатный сценарий

| Часть | Состояние |
| --- | --- |
| Главный экран и форма | Готовы: вводная часть, форма, согласие, язык ответа, объяснение процесса и FAQ |
| Ожидание | Готово: сохранение, обработка, готовый ответ; без ложных процентов выполнения |
| Результат | Готов: текст, опорные детали, вопрос; фокус переносится к ответу, reload восстанавливает задание |
| Ошибки и недоступность | Готовы: сохранение черновика, восстановление связи, запрет отправки при недоступности |
| Причина блокировки отправки | Опубликована рядом с кнопкой: связь, диктовка, длина, согласие, сохранение; при готовности показано явное подтверждение. Ошибка отправки тоже рядом с кнопкой |
| Повтор и неопределённая отправка | Повтор отключён при offline; неопределённая отправка требует проверки оператором |
| Новый сон | Исправлено: предыдущие текст, чувство и согласие очищаются |
| Удаление | `DELETE` физически удаляет строку задания и служебную запись выдачи на сервере, в том числе для активного задания; история ChatGPT и резервные копии удаляются отдельно |
| Языки интерфейса | Рабочий `/bridge` полностью доступен на RU/EN; язык интерфейса и язык результата переключаются согласованно |
| Мобильная вёрстка | Проверены 390 и 320 px, отсутствие горизонтального переполнения, переносы кнопок и результата |
| Доступность | Подписи полей, видимый фокус, переход к содержимому, автоматический фокус результата, кнопки от 44 px |
| Голосовой компонент | Проверены имитационные события: остановка, ошибки, восстановление текста; форма и язык блокируются во время записи |
| Настоящий микрофон | Windows Chrome подтверждён. Телефон: повторный скриншот 21:48 подтверждает текст без нарастающих повторов и готовый разбор в попытке 1 после исправления |

Проверки: production build с TypeScript; 181 Python-тест API, очереди,
исполнителя, изоляции сессий и резервного копирования. Последний browser-набор:
72 проверки bridge+voice на desktop/mobile; прежний общий набор описан в истории.
Браузерная матрица включает оба языка интерфейса, физический `DELETE`, восстановление
опроса после сетевого сбоя, диктовку с имитацией браузерных событий и узкие экраны.
Сценарии обработки используют имитацию ChatGPT-ответа или локальное демо. Это не
новая живая серия генераций и не проверка настоящего микрофона.

Интерфейс опубликован на существующем тестовом VPS. Публичная smoke-проверка
подтвердила редирект корня на `/bridge`, HTTP 200 страницы и favicon, CSP и другие
защитные заголовки шлюза, работу RU/EN, отсутствие ошибок JavaScript и горизонтального
переполнения на desktop/mobile. Живая конфигурация сообщает
`automatic_dispatch=true`, `synthetic_only=true`; текущее состояние исполнителя
показывается на сайте, при offline отправка блокируется с пояснением. После
восстановления исполнителя реальная диктовка пользователя отправлена; разбор
восстановлен оператором после исправления чтения пробелов и виден на сайте.
Артефакты предыдущей визуальной проверки:
`.cache/frontend-validation/live-report.json`, `live-desktop.png`,
`live-mobile.png`, `live-narrow.png` (локальные, вне Git).

## Что остаётся по интерфейсу

1. Мобильная диктовка — проверена после исправления: скриншот пользователя 21:48
   показывает текст без повторов и готовый разбор в попытке 1. Запрос промежуточных
   результатов отключён, текст появляется после паузы/остановки. 34 голосовых теста
   desktop/mobile и production build прошли. Другие модели устройств и браузеры
   этим единичным реальным тестом не покрыты.
   После сообщения пользователя о неактивной отправке добавлено пояснение рядом
   с кнопкой на RU/EN. Две проверки desktop/mobile подтверждают, что восстановление
   связи включает кнопку без потери уже введённого текста; production build прошёл.
2. После определения модели хранения/удаления синхронизировать с ней согласие и
   сообщения интерфейса. Сейчас они честно описывают ограниченный тестовый режим.
3. Для платной версии: экран глубокого разбора, переход к оплате, ожидание оплаты,
   успех/отказ/возврат пользователя. Ориентир только на UI — 2–3 рабочих дня после
   согласования продукта и API оплаты. Серверная интеграция и подключение продавца
   в этот срок не входят.

## Что не закрывается вёрсткой

Изоляция контекста посетителей в ChatGPT, ограничение запросов, хранение/удаление
всех копий и длительное наблюдение. Порог десяти разных полных живых прогонов
достигнут; это не серия без ошибок. До завершения остальных пунктов
режим только для вымышленных снов сохраняется. Вёрстка бесплатного сценария не
означает готовность принимать личные сны в публичном production.
