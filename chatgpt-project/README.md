## Состав и порядок уже выполненной загрузки

1. Проверить существующие проекты, чтобы не создать дубликат. Создать проект с указанным названием и закрепить его.
2. Вставить содержимое PROJECT_INSTRUCTIONS.md в инструкции проекта.
3. Добавить STYLE_GUIDE.md, CULTURAL_GAPS.md, RESEARCH_NOTES.md и SOURCE_CATALOG.json как файлы базы знаний. Это собственные заметки и библиография 12 источников, без полных статей и личных дневников.
4. Для испытания моста добавить BRIDGE_CONTRACT.md, две схемы из schemas и три JSON из examples. Если интерфейс ограничивает число файлов, сначала загрузить четыре файла базы знаний; схемы и пример можно приложить к отдельному тестовому сообщению.
5. Проверить в интерфейсе имена/готовность каждого файла и сохранённые инструкции. Записать подтверждённые URL и загруженные SHA256 в PROJECT_STATUS.json. Локальный manifest подтверждает содержимое пакета, но не его загрузку или retrieval.

Разрешённые файлы перечислены в UPLOAD_MANIFEST.json с SHA256. Не загружать .env, data, исходные личные сны, исходный DOCX, историю задач или весь репозиторий. README и manifest нужны для подготовки, а не как дополнительные инструкции модели.

## Ручной первый тест после настройки проекта

«Это синтетический ручной тест Sonnic. Прочитай доступные инструкции, STYLE_GUIDE.md и CULTURAL_GAPS.md. Обработай приложенный blue-parrot.input.json и верни JSON по output.schema.json. Мост пока не подключён, поэтому не вызывай несуществующие инструменты и не утверждай, что результат отправлен на сайт. Перечисли в source_use только действительно просмотренные заметки; допустим пустой список».

Ожидаемое качество: учитываются птица и синий цвет, не придумываются полёт/клетка/разговор/эмоции, задаётся один полезный вопрос. blue-parrot.output.json — вручную написанный ориентир, не полученный от ChatGPT ответ и не единственная допустимая формулировка. Остальные шесть сценариев проверяют контрасты и язык. Первый живой ручной blue-parrot тест оценён в validation/blue-parrot.review.md; остальные шесть сценариев ещё не проверены моделью.

## Локальная проверка

Из корня Sonnic:

```powershell
.venv\Scripts\python.exe scripts/build_chatgpt_package.py
.venv\Scripts\python.exe -m pytest tests/bridge -q --basetemp=.cache/pytest-bridge
.venv\Scripts\python.exe scripts/check_chatgpt_bridge.py
```

Сборка обновляет только allowlist пакета и не изменяет PROJECT_STATUS.json. Проверка проходит очередь до публичной проекции на вручную подготовленном ответе. `.cache/bridge-preview.json` — результат локального теста; он не опубликован в работающем сайте. Сеть, ключ API и платные вызовы не используются.

Проект создан ранее, заполнен и проверен вручную. Следующий технический шаг — авторизованный HTTPS MCP и запуск задания из ChatGPT по запросу оператора. Secure MCP Tunnel требует runtime API key и не подходит под действующее условие без API-ключей. Автоматический запуск произвольного проекта из сайта пока не подтверждён и не реализован; готовый пакет этого не меняет.
