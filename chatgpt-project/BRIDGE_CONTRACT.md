# Sonnic ↔ ChatGPT: контракт sonnic-project-v1

Исторический статус MCP на 2026-09-07: HTTPS MCP-мост развёрнут и проверен живым вызовом ChatGPT. Закрытый персональный бета-ввод разрешён только владельцу проекта; запуск обычной подписки ChatGPT требует отдельного сообщения владельца.

## Автоматический транспорт — 2026-09-08

Реализован отдельный служебный API `/api/v1/bridge/worker/{heartbeat,claim,renew,fail,submit}`.
Он включается `SONNIC_AUTOMATIC_DISPATCH=true` и требует отдельный Bearer-секрет
`SONNIC_WORKER_TOKEN` длиной не менее 32 символов. Секрет не передаётся модели или посетителю.
Служебный claim атомарно выдаёт старейший доступный job независимо от гостевой сессии,
сохраняя её владельца для показа результата. Повтор claim использует сохранённый UUID.
Аренда 120 секунд продлевается каждые 15 секунд до общего срока 600 секунд.
`submit` проверяет контракт, корреляцию, locale и дословность evidence и переводит
служебный job сразу в completed. Повтор идентичного ответа идемпотентен.

Исполнитель `python -m apps.worker.main` использует отдельный профиль Chrome/порт 9335,
открывает новый чат именно проекта Sonnic и передаёт полный job с инструкциями и заметками.
Модель возвращает JSON в чат и не вызывает MCP. Журнал сохраняет намерение отправки,
URL чата и полученный ответ. При неопределённости отправка не повторяется автоматически.
После подтверждения доставки локальные текст/ответ удаляются из активного журнала;
остаётся техническая квитанция. История в ChatGPT сохраняется отдельно.

Первое включение ограничено вымышленными снами (`SONNIC_WORKER_ALLOW_PERSONAL=false`).
Независимость гостевых cookie не доказывает изоляцию памяти модели.
Статус живой проверки и оставшаяся работа находятся в docs/STATUS_AND_COMPLETION_PLAN.md.
`origin_verified=false` сохраняется: техническая валидация не доказывает происхождение ответа.

## Диагностический MCP: направление работы

Владелец в ChatGPT просит обработать конкретный job. ChatGPT вызывает `claim_job`, готовит JSON и вызывает `submit_result`. Сервер проверяет ответ и сохраняет awaiting_review. Владелец проверяет текст на сайте, после чего результат становится видимым в его браузерной сессии. Создание задания сайтом само по себе не запускает обычный проект ChatGPT.

Документация [Developer mode](https://developers.openai.com/api/docs/guides/developer-mode) описывает вызовы MCP из ChatGPT. [Подключение приложения](https://developers.openai.com/plugins/deploy/connect-chatgpt) описывает HTTPS MCP или Secure MCP Tunnel. Эти документы не подтверждают автоматический запуск произвольного проекта ChatGPT из backend Sonnic. Совместимость приложения с конкретным проектом, подпиской и его памятью требует фактической проверки. Туннель, учётные данные подключения и транспорт ещё не настроены. Ключ OpenAI API не используется.

## Будущие инструменты

| Инструмент | Аргументы модели | Результат | Полномочие | Изменяет состояние |
| --- | --- | --- | --- | --- |
| claim_job | job_id UUID, claim_key UUID | input.schema.json | worker | Да: резервирует обработку |
| submit_result | output.schema.json | awaiting_review или completed при идентичном повторе | worker | Да: сохраняет кандидата |

Для обоих нужны `readOnlyHint: false`, `openWorldHint: false`, `destructiveHint: false`, `idempotentHint: true` с учётом ключа/неизменного тела. Подтверждения записи управляются ChatGPT; код их не обходит. В модели нет инструментов review, enqueue, retry, cancel, произвольного поиска заданий или чтения чужих данных. Status/result доступны авторизованной стороне сайта; review — отдельно оператору. Отправка кандидата не означает публикацию.

Идентичный claim допускается только для того же worker и действующей lease. Повтор submit с тем же телом допускается в awaiting_review/completed; исправленное тело не перезаписывает прежний результат. Для исправления оператор отклоняет кандидата, сторона сайта запускает новую попытку с новой lease. Все остальные повторы и просроченные пакеты отклоняются явно.

## Аутентификация и изоляция

`Principal(subject, owner, scopes)` формируется HTTP-адаптером из HttpOnly cookie владельца или OAuth-токена, привязанного к той же сессии. Сервер проверяет audience, срок и scope. Модель не может передавать owner, права, путь файла или callback URL. UUID не даёт права доступа. Публичного NoAuth-доступа нет.

Очередь принимает семь фиксированных синтетических примеров и произвольный `DreamInput` от браузерной сессии владельца. Личный ввод получает `data_class=personal`, требует явного согласия в интерфейсе и доступен ChatGPT только после owner-bound OAuth и точного `job_id`/`claim_key`. Это закрытый однопользовательский бета-режим, а не готовая обработка снов разных клиентов.

Для публичного многопользовательского трафика по-прежнему нужен отдельный контур для каждого клиента: учётные записи, независимая память, сроки хранения и проверки пересечения данных. Текущий проект ChatGPT принадлежит одному владельцу, поэтому его нельзя использовать как общий backend для клиентов.

## Данные и состояния

Вход содержит contract_version, knowledge_version, job_id, lease_id, attempt, input_sha256, data_class (`synthetic` или `personal`), output_locale и dream. Хеш — SHA256 UTF-8 canonical JSON полного DreamInput с defaults, ключами в алфавитном порядке, без пробелов, ensure_ascii=false. Он связывает ответ с запросом, но не является подписью происхождения.

Выход содержит те же версии и идентификаторы, locale, outcome, reflection либо safe_message, source_use. Дополнительные поля запрещены. Для reflection/needs_context требуется reflection и null safe_message; для support/refused — наоборот. Evidence каждого symbol должно быть дословной подстрокой dream_text. JSON-валидация не доказывает качество, истинность текста или отсутствие опасного содержания. `source_use` — самоотчёт о просмотренных заметках, не доказательство retrieval.

Состояния: queued → leased → awaiting_review → completed. Отклонение проверки даёт failed; общий срок или lease — expired; отмена — cancelled. Retry доступен только для failed/expired и не более трёх попыток. Lease 10 минут, общий срок одной постановки 60 минут, максимум 20 активных заданий и одна одновременная lease. Перезапуск не теряет задания: SQLite сохраняет корреляцию и состояния. Проверка истечения выполняется при операциях, фонового планировщика нет.

Cancel/«Удалить сон» очищает вход и кандидат из строки, оставляя tombstone идемпотентности. Это логическое удаление и не гарантирует немедленное физическое стирание страниц SQLite или резервных копий. База не зашифрована, поэтому закрытый бета-режим нельзя открывать клиентам до отдельной работы с хранением.

## Возврат для сайта

`Queue.result_for_site` допускается только для completed и возвращает mode=bridge_contract_preview, origin_verified=false, data_class, locale, outcome, reflection, safe_message. Внутренние source_use, owner, lease и хеши не попадают в проекцию. Отметка origin_verified=false обязательна: транспорт не даёт криптографического доказательства происхождения текста из конкретной модели.

Рабочий маршрут `/bridge` сопоставляет job с cookie владельца и отображает ответ как текст, не HTML. `UnconnectedProjectTransport.request_processing` сохраняет явную ошибку для будущего автоматического запуска, чтобы ручной шаг не выглядел серверной автоматизацией.

Примеры blue-parrot составлены вручную. Их фиксированные UUID иллюстрируют схему; для реальной тестовой lease берутся значения из claim. CLI `scripts/check_chatgpt_bridge.py` подставляет текущую lease только в локальном тесте и не вызывает ChatGPT.
