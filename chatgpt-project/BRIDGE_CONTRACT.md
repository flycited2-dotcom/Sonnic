# Sonnic ↔ ChatGPT: контракт sonnic-project-v1

Статус 2026-09-06: реализовано локальное ядро очереди `apps/bridge`, без HTTP/MCP-сервера, подключения ChatGPT и изменения сайта. Этот документ описывает будущую границу инструментов. Названия ниже пока не являются доступными инструментами ChatGPT.

## Направление работы

Оператор в ChatGPT выбирает подключённое приложение и просит обработать конкретный synthetic job. ChatGPT вызывает `claim_job`, готовит JSON и вызывает `submit_result`. Сервер проверяет ответ и сохраняет awaiting_review. Отдельный человек проверяет текст, затем локальный слой доставки разрешает получить публичный результат. Создание задания сайтом само по себе не запускает ChatGPT.

Документация [Developer mode](https://developers.openai.com/api/docs/guides/developer-mode) описывает вызовы MCP из ChatGPT. [Подключение приложения](https://developers.openai.com/plugins/deploy/connect-chatgpt) описывает HTTPS MCP или Secure MCP Tunnel. Эти документы не подтверждают автоматический запуск произвольного проекта ChatGPT из backend Sonnic. Совместимость приложения с конкретным проектом, подпиской и его памятью требует фактической проверки. Туннель, учётные данные подключения и транспорт ещё не настроены. Ключ OpenAI API не используется.

## Будущие инструменты

| Инструмент | Аргументы модели | Результат | Полномочие | Изменяет состояние |
| --- | --- | --- | --- | --- |
| claim_job | job_id UUID, claim_key UUID | input.schema.json | worker | Да: резервирует обработку |
| submit_result | output.schema.json | awaiting_review или completed при идентичном повторе | worker | Да: сохраняет кандидата |

Для обоих нужны `readOnlyHint: false`, `openWorldHint: false`, `destructiveHint: false`, `idempotentHint: true` с учётом ключа/неизменного тела. Подтверждения записи управляются ChatGPT; код их не обходит. В модели нет инструментов review, enqueue, retry, cancel, произвольного поиска заданий или чтения чужих данных. Status/result доступны авторизованной стороне сайта; review — отдельно оператору. Отправка кандидата не означает публикацию.

Идентичный claim допускается только для того же worker и действующей lease. Повтор submit с тем же телом допускается в awaiting_review/completed; исправленное тело не перезаписывает прежний результат. Для исправления оператор отклоняет кандидата, сторона сайта запускает новую попытку с новой lease. Все остальные повторы и просроченные пакеты отклоняются явно.

## Аутентификация и изоляция

`Principal(subject, owner, scopes)` сейчас передаётся доверенным локальным Python-кодом. Это **не готовая сетевая аутентификация**. Будущий адаптер обязан получать subject/owner/scopes из проверенной сервером учётной записи, проверять audience/срок/область токена и сопоставлять владельца на сервере. Модель не может передавать owner, права, путь файла или callback URL. UUID не даёт права доступа. Публичный NoAuth endpoint недопустим.

Очередь принимает только case_id из семи фиксированных синтетических примеров. Реальный dream_text через enqueue передать нельзя. Это тестовый этап, а не готовая обработка личных снов. Общий knowledge project содержит только публичные заметки и вымышленные тесты; чаты внутри него не доказывают изоляцию разных пользователей.

Для реального трафика нужен отдельно проверенный контур для каждого владельца: отсутствие общей памяти/истории личных снов, серверная привязка учётной записи к пространству, независимая авторизация получения/возврата, сроки удаления, согласие на передачу и проверки пересечения данных между пользователями. Пока свойства ChatGPT-проекта и транспорта не подтверждены испытанием, расширять allowlist до произвольного текста нельзя. Локальные owner-проверки сами по себе не защищают память внешней модели.

## Данные и состояния

Вход содержит contract_version, knowledge_version, job_id, lease_id, attempt, input_sha256, data_class=synthetic, output_locale и dream. Хеш — SHA256 UTF-8 canonical JSON полного DreamInput с defaults, ключами в алфавитном порядке, без пробелов, ensure_ascii=false. Он связывает ответ с запросом, но не является подписью происхождения.

Выход содержит те же версии и идентификаторы, locale, outcome, reflection либо safe_message, source_use. Дополнительные поля запрещены. Для reflection/needs_context требуется reflection и null safe_message; для support/refused — наоборот. Evidence каждого symbol должно быть дословной подстрокой dream_text. JSON-валидация не доказывает качество, истинность текста или отсутствие опасного содержания. `source_use` — самоотчёт о просмотренных заметках, не доказательство retrieval.

Состояния: queued → leased → awaiting_review → completed. Отклонение проверки даёт failed; общий срок или lease — expired; отмена — cancelled. Retry доступен только для failed/expired и не более трёх попыток. Lease 10 минут, общий срок одной постановки 60 минут, максимум 20 активных заданий и одна одновременная lease. Перезапуск не теряет задания: SQLite сохраняет корреляцию и состояния. Проверка истечения выполняется при операциях, фонового планировщика нет.

Cancel очищает вход и кандидат из строки, оставляя tombstone идемпотентности. Это не гарантированное физическое стирание SQLite/резервных копий. База не зашифрована, автоматического удаления завершённых записей нет; в текущем прототипе данные только вымышленные.

## Возврат для сайта

`Queue.result_for_site` допускается только для completed и возвращает mode=bridge_contract_preview, origin_verified=false, data_class=synthetic, locale, outcome, reflection, safe_message. Внутренние source_use, owner, lease и хеши не попадают в проекцию. Отметка origin_verified=false обязательна: ручной JSON не доказывает происхождение из ChatGPT.

Это подготовленный контракт доставки, ещё не маршрут работающего сайта. Сайт сейчас показывает demo. Продуктовый адаптер должен отдельно сопоставлять job с записью сайта и отображать текст безопасно как текст, не HTML. `UnconnectedProjectTransport.request_processing` явно возвращает ошибку chatgpt_project_transport_not_connected, чтобы отсутствие транспорта не выглядело успешным запуском.

Примеры blue-parrot составлены вручную. Их фиксированные UUID иллюстрируют схему; для реальной тестовой lease берутся значения из claim. CLI `scripts/check_chatgpt_bridge.py` подставляет текущую lease только в локальном тесте и не вызывает ChatGPT.
