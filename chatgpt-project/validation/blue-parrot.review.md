# Живой ручной тест ChatGPT: синий попугай

Дата: 2026-09-06. [Фактический тестовый чат «Обработка JSON сна»](https://chatgpt.com/g/g-p-6a9c47e07510819197bd898c90d1b12b-sonnic-baza-znanii-i-razbor-snov/c/6a9d91ac-7f0c-83eb-a745-71c21114c9a8).

## Проведение

В существующий проект Sonnic штатным filechooser загружены все 11 файлов из UPLOAD_MANIFEST.json. После обработки каждый файл отображался отдельным источником с датой 6 сентября. Дубликатов не создавали. Название, полные инструкции и режим памяти только проекта проверены ранее; проект закреплён.

Оператор через браузер отправил синтетический запрос прочитать инструкции, стиль, ограничения культур, blue-parrot.input.json и output.schema.json, самостоятельно разобрать вход, учитывать доступные RESEARCH_NOTES и вернуть строгий JSON. Прямо указано, что мост не подключён, web-поиск не нужен и результат нельзя объявлять отправленным на сайт. Исходные данные и схему не копировали в сообщение: модель обращалась к контексту проекта. Доступность содержимого конкретного файла техническим журналом retrieval не подтверждена; совпадение входных полей и самоотчёт об источниках — более ограниченное свидетельство.

Файл blue-parrot.chatgpt-output.json содержит фактические поля видимого ответа, перенесённые из UI с нормализацией форматирования JSON. Это отдельный артефакт, исходный написанный вручную examples/blue-parrot.output.json не заменён. Ориентир был доступен модели в проекте, поэтому этот прогон не является слепой независимой оценкой.

Небольшое замечание: последний вопрос объединяет действие птицы и чувство пользователя в одной фразе. Для короткого рассказа можно предпочесть один фокус, но обязательную схему это не нарушает. Ответ несколько осторожнее и длиннее, чем нужно для одной строки; это редакционное улучшение, не ошибка контракта. Остальные шесть сценариев живой моделью в этом этапе не проверялись.

Этот прогон подтверждает ручную работу проекта с тестовым заданием. Он не подтверждает авторизованный сетевой транспорт, автоматический запуск из сайта, качество на личных снах или изоляцию разных пользователей. Фиксированные UUID примера не относятся к действующей lease локальной очереди; ответ не подавался туда с подменой идентификаторов и не опубликован в UI Sonnic.

## Следующий транспорт без API-ключей

По [официальной документации Secure MCP Tunnel](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels#before-you-start) клиент туннеля требует runtime API key. Поэтому этот путь исключён при действующем условии владельца «без API-ключей»; ключ не запрашивался и туннель не создавался.

Документированная альтернатива — [подключение публичного MCP endpoint](https://developers.openai.com/plugins/deploy/connect-chatgpt#add-the-mcp-server). Для Sonnic ещё нет проверенного HTTPS endpoint с авторизацией и сопоставлением владельцев. Публичный NoAuth и публикация локальной очереди не применялись. Настроенного инструмента Sonnic в просмотренном меню приложений проекта нет. Прежде чем подключать сеть, нужен отдельный транспорт и проверка прав; автоматическое пробуждение произвольного проекта сайтом этими документами не установлено.
